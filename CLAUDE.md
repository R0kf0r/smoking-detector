# Детектор курения — хакатон «Видеофор» (Гатчина, 8–10.10.2026)

Цель: по видео со стационарных уличных камер находить эпизоды поведения, похожего на курение, и выдавать события в формате организаторов.
Требования — @docs/SPEC.md (главный источник). Исследование — `docs/research.md`: читай его, когда выбираешь модели, данные или лицензии.

## Приоритеты

1. Корректность: Event F1 по протоколу SPEC §6. План — `docs/ACCURACY.md`.
2. Устойчивость к условиям съёмки: сезоны, ночь.
3. Потенциал удешевления.
4. Внешний вид по `docs/DESIGN.md`.

При конфликте побеждает пункт выше. Любое изменение, которое может повлиять на точность, подтверждай цифрами оценщика «до» и «после» на одном и том же наборе.

Сроки: все материалы к защите — до 23:59 9 октября. Скрытый набор снимают 9-го днём, поэтому обработка должна укладываться в бюджет времени, замеренный на эталоне.

## Окружение

- macOS, Apple Silicon. Ускоритель PyTorch — `mps`, CUDA нет.
- Python 3.12 в conda-окружении `smoke`. Все команды Python запускай так: `conda run --no-capture-output -n smoke python ...`
- Зависимости: `requirements.txt` (база, уже установлена) и `requirements-extra.txt` (интерфейс, запасная модель позы, клиент Ollama — ставить, когда дойдём до этих шагов). Новую библиотеку добавляй в нужный файл.
- Локальная VLM: по умолчанию `mlx-vlm` с `mlx-community/Qwen3-VL-4B-Instruct-4bit`; запасной вариант — Ollama (`qwen3-vl`, размер по памяти, таблица в `docs/research.md`). Только локальные модели.
- Трекер BoT-SORT: `appearance_thresh` — минимальная похожесть (0.8 и выше), не 0.25. Время кадра — по меткам времени видео, не номер кадра / fps. Видео с отметками — через ffmpeg (libx264, yuv420p).

## Жёсткие правила

- IMPORTANT: в `private/` лежит видео с объекта. Правила хакатона запрещают передавать его в облачные сервисы, а значит, и тебе. Не читай файлы из `private/`, не извлекай из них кадры и не открывай картинки и видео, полученные из них, где бы они ни лежали. Отлаживай только по числам: координаты, расстояния, тайминги, метрики. Запускать скрипты, которые локально обрабатывают `private/`, можно.
- Обработанные ролики и кадры из видео объекта сохраняй только в `private/renders/`. В `results/` пиши только числа: события, сигналы, метрики.
- Не открывай в своей панели браузера страницы, где показывается видео с объекта (интерфейс, проигрыватель). Внешний вид проверяй только на публичных роликах из `data/public/`.
- Ссылки на облако с видео объекта не открывай и не скачивай: это делает человек вручную.
- Разметка эталона — `labels/reference.csv` (только время и метки, без кадров), её можно читать.
- Не используй облачные API и облачные модели для кадров и видео, включая теги Ollama с `-cloud`.
- После git-тега `freeze-*` не меняй пороги, постобработку и модели.
- Все пороги и параметры храни в `configs/default.yaml`, не в коде.
- Каждую модель, датасет и шрифт записывай в `docs/manifest_notes.md`: название, версия, источник, лицензия.
- Прежде чем сказать «готово», запусти тесты (и валидатор организаторов, когда он появится в `tools/validator/`) и покажи вывод.
- Работай маленькими шагами. После каждого рабочего шага предлагай git commit с понятным сообщением.
- Объясняй решения по-русски, коротко.

## Архитектура (цель; подробно — `docs/ACCURACY.md`)

1. Этап A, кандидаты:
   - YOLO26-pose плюс BoT-SORT с ReID, затем офлайн-склейка треклетов;
   - сигнал «кисть у рта», нормированный на размер человека;
   - автомат циклов: подход → пауза 0,5–5 с → отход;
   - результаты тяжёлого прогона (рамки, ID, точки) кэшируются в `results/cache/`, правила и пороги считаются из кэша.
2. Этап B, проверка кандидатов: локальная VLM по кадрам паузы у рта, вето по предметам COCO, кинематика.
3. Этап C, события строго по SPEC §3–4.
4. Выход: события в JSON/CSV, `manifest.json` и видео с отметками по `docs/DESIGN.md`.

## Состояние кода (v6)

Ядро уже написано и покрыто тестами (`smokedet/`, `tests/`): конвейер, оценщик, правила, VLM-проверка, рендер, подбор порогов. Не переписывай модули с нуля: чини точечно и подтверждай тестами и метриками «до/после».

## Команды

- Тесты: `conda run --no-capture-output -n smoke python -m pytest -q`
- Опись и заготовка разметки: `conda run --no-capture-output -n smoke python -m smokedet.inventory private/reference --labels-template labels/reference.csv --guess-labels`
- Прогон эталона: `conda run --no-capture-output -n smoke python -m smokedet.run --input private/reference --out-dir results/reference --render-dir private/renders/reference --gt labels/reference.csv`
- Подбор порогов: `conda run --no-capture-output -n smoke python -m smokedet.calibrate --run-dir results/reference --gt labels/reference.csv` (`--apply` записывает в конфиг)
- Оценка по протоколу: `conda run --no-capture-output -n smoke python -m smokedet.evaluate --pred results/reference/events.json --gt labels/reference.csv --durations results/reference/timing.csv`
- Скрытый набор: `conda run --no-capture-output -n smoke python -m smokedet.run --input private/hidden --out-dir results/hidden --camera-id <камера>`
- Отлаживай по числам: `results/<прогон>/debug/<clip_id>.json` (циклы, отклонённые паузы, голоса VLM) и `signals/<clip_id>.csv`.
